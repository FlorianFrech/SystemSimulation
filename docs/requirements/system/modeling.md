# Derived System Requirements: Modeling

|U-ID    | SR-ID    | System Requirement | Rationale | Priority |
|-------|----------|--------------------|-----------|----------|
| UR_01 | SR_01_01 | The framework shall allow users to define and instantiate reusable component models for different physical domains. | Supports modularity and reuse, allowing users to encapsulate behavior of domain-specific subsystems (e.g., motors, sensors, controllers) | Shall |
| UR_01 | SR_01_02 | The framework shall provide a unified interface for connecting components across different physical domains. | Ensures interoperability and proper coupling of domain-specific models (e.g., linking electrical and mechanical components). | Shall |
| UR_02 | SR_02_01 | The system shall associate a unit with every model parameter, variable, input, and output. | This ensures all physical quantities are traceable and validates that units are explicitly defined at every modeling interface. | Shall |
| UR_02 | SR_02_02 | The system shall validate unit compatibility when connecting components or assigning parameter values. | Prevents errors due to incompatible units, ensuring physical correctness of models. | Shall |
| UR_02 | SR_02_03 | The system shall support automatic conversion of compatible units to a common base unit system (e.g., SI units). | Enables seamless model integration and simulation even when component authors use different unit systems (e.g., m/s vs. km/h). | Shall |
| UR_03 | SR_03_01 | The framework shall support hierarchical composition of system models from individual subsystems. | Reflects the system architecture and enables scalable modeling by assembling smaller building blocks. | Shall |
| UR_03 | SR_03_02 | The framework shall provide standardized interface variables for defining subsystem inputs and outputs. | Facilitates correct and consistent interconnection of subsystems, ensuring data flow and signal compatibility. | Shall |
| UR_03 | SR_03_03 | The framework shall support the resolution of execution order in hierarchical graphs. | Ensures that all dependencies are respected and that the simulation can proceed in a logically consistent manner. | Shall |
| UR_03 | SR_03_04 | The framework shall validate the structure of the resulting system before simulation. | Ensures that the assembled model is complete and consistent, preventing runtime errors during simulation. | Shall |
| UR_03 | SR_03_05 | The framework should allow graphical connection of subsystem models. | Enhances usability and understanding of system architecture by providing a visual representation of connections. | Should |
| UR_04 | SR_04_01 | The framework should support bidirectional connectors to exchange variables between components. | Acausal modeling relies on connectors that transmit information without predefined causality, requiring a flexible port mechanism. | Should |
| UR_04 | SR_04_02 | The framework should parse user-defined equations and construct a symbolic representation of the model. | This enables more flexible modeling approaches and allows users to define complex relationships between variables. Required for further processing (e.g., causality analysis, index reduction). | Should |
| UR_04 | SR_04_03 | The framework should identify and classify equations as differential, algebraic, or event-related. | Helps categorize model behavior and support hybrid simulation. | Should |
| UR_04 | SR_04_04 | The framework should perform computational causality analysis to determine which variables must be solved and in what order. | Important for converting models into solvable simulation-ready structures. | Should |
| UR_04 | SR_04_05 | The framework should detect and handle algebraic loops using symbolic or numerical methods. | Required to ensure the model can be evaluated during simulation (e.g., Newton-Raphson, tearing). | Should |
| UR_04 | SR_04_06 | The framework should support index analysis and apply index reduction methods (e.g., Pantelides algorithm) when required. | Ensures solvability of higher-index DAE systems. | Should |
| UR_05 | SR_05_01 | The framework shall allow the definition of components with explicitly declared input and output variables. | In causal modeling, each component must have well-specified interfaces to allow clear information flow. | Shall |
| UR_05 | SR_05_02 | The framework shall support the transformation of causal equations into executable functions. | Causal equations should be converted to deterministic computation steps (e.g., function evaluations) during simulation. | Shall |
| UR_05 | SR_05_03 | The framework shall integrate with ODE solvers for forward simulation. | Causal systems typically reduce to ordinary differential equations, which can be directly solved using standard numerical integrators. | Shall |
| UR_05 | SR_05_04 | The framework shall validate the consistency of input-output relationships in component models. | Causal modeling depends on correct directionality. This requirement ensures each component has a valid computational graph without ambiguous data flow. | Shall |
| UR_05 | SR_05_05 | The framework shall support hierarchical composition of causally connected components. | Enables the construction of complex systems from simpler subsystems, promoting reuse and maintainability. | Shall |
| UR_05 | SR_05_06 | The framework shall detect and solve algebraic loops that arise from causally connected components. | Algebraic loops occur when variables are mutually dependent within the same computation step. The framework must automatically detect these loops and apply appropriate numerical techniques (e.g., fixed-point iteration, Newton-Raphson) to resolve them. | Shall |
| UR_06 | SR_06_01 | The system shall support modeling elements with discrete-time update rules (e.g., difference equations, sampling intervals). | Enables digital or sampled system components to be represented faithfully, such as controllers, software models, or sampled-data systems. | Shall |
| UR_06 | SR_06_02 | The system shall allow components to define switching logic or events that affect continuous dynamics. | Hybrid systems require mechanisms to detect and react to conditions (e.g., zero-crossings) that trigger mode changes in dynamics. | Shall |
| UR_06 | SR_06_03 | The system shall provide simulation capabilities that can handle mixed continuous and discrete-time dynamics with proper solver coordination. | Simulation engines must synchronize time steps and event handling across continuous and discrete domains to maintain accuracy and stability in hybrid models. | Shall |
| UR_06 | SR_06_04 | The system shall support the reinitialization of continuous states in response to discrete events or switching conditions. | Hybrid systems often involve abrupt changes (e.g., switches, resets, impulses) that require discontinuous jumps or redefinitions of continuous state variables. To accurately simulate such behavior, the simulation framework must be capable of detecting these events and reinitializing affected state variables accordingly. | Shall |
| UR_07 | SR_07_01 | The framework should define a library of reusable templates for common physical components. | Enables users to instantiate typical elements without redefining their equations, ensuring consistency and speeding up the model-building process. | Should |
| UR_07 | SR_07_02 | The framework should support user-defined templates for custom component types. | Allows extensibility beyond built-in templates, supporting domain-specific needs and expert modeling capabilities. | Should |
| UR_07 | SR_07_03 | The framework should ensure that templates support parameterization and unit annotation. | Parameterization and unit safety are essential for template usability across different scenarios and for correct interpretation during simulation. | Should |
| UR_08 | SR_08_01 | The framework shall support parameterized instantiation of components and subsystems. | Parameters enable variation in behavior without changing the underlying model definition, facilitating reuse across different configurations. | Shall |
| UR_08 | SR_08_02 | The framework shall allow multiple instances of the same model template with independent settings. | This capability is essential for simulating different scenarios or configurations without duplicating model definitions. | Shall |
| UR_08 | SR_08_03 | The framework shall support hierarchical composition of reusable subsystems. | Hierarchical composition enables the construction of complex systems from simpler, reusable subsystems, promoting modularity and ease of maintenance. | Shall |
