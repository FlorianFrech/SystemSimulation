\section{Co-Simulation Principles and Algorithms}\label{sec:theory_co_simulation}

\subsection{From Monolithic Simulation to Co-Simulation}
In a monolithic simulation, all subsystem models are formulated within a single modeling environment and assembled into one global equation system.
A single solver advances the combined system and has access to all equations and variables at every time instant.
Modelica-based simulation is a representative example of this approach~\cite{Modelica_Fritzson}.

When subsystem models originate from different tools, they can be exported as equation representations and assembled by a host environment that provides a single solver for the combined system.
This approach is called model exchange (sometimes referred to as \emph{strong coupling} in the literature).
Because one solver processes all equations, it can enforce numerical consistency 
across all subsystems.
Its limitation is that the host solver must accommodate the requirements of all subsystems simultaneously~\cite{gomes_co-simulation_2019}.

Co-simulation (sometimes referred to as \emph{weak coupling}) adopts a different strategy.
Each simulation unit retains its own solver and advances autonomously between discrete communication points $T_k$.
A master algorithm orchestrates the coupled execution.
At each communication point, it collects outputs from all simulation units, distributes them as inputs to connected units, and commands each unit to advance to $T_{k+1}$.
Between communication points, each simulation unit integrates independently with its internal step size $\Delta t_{i,r} \leq H_k$.
The master algorithm has no access to the internal equations of any simulation unit.
This black-box property is the defining characteristic of co-simulation and distinguishes it from model exchange~\cite{gomes_co-simulation_2019}.
