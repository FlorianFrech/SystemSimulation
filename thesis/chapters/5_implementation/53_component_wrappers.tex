\section{Component Wrappers}
\label{sec:impl_wrappers}

This section describes how backend-specific models are adapted to the common \texttt{CoSimComponent} contract.
The three adapters differ deliberately in abstraction level.
\texttt{FMUComponent} is the most generic wrapper, because FMI already defines a standardized co-simulation interface, a model-description file, typed value references, parameters, and structural dependency metadata.
\texttt{OpenSimComponent} provides a thinner abstraction.
It supplies a common runtime pattern based on \texttt{Model}, \texttt{State}, and \texttt{Manager}, but the exposed ports, parameters, and model assembly remain specific to each musculoskeletal model.
For finite-element models, the reusable abstraction is even smaller. 
The framework provides only a minimal convenience base for common FE-related
containers and optional file/output hooks.
The actual discretization, material law, solver state, boundary conditions, and state-transfer semantics are owned by the concrete FE component.

This asymmetry is a consequence of the backends themselves rather than an inconsistency of the framework design.
Reusable abstractions are introduced only where the backend provides a stable interface or where repeated implementation patterns exist.
