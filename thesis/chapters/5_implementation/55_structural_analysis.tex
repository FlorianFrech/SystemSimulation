\section{Structural Analysis and Execution Ordering}
\label{sec:impl_structural}

The structural-analysis implementation derives persistent execution metadata from the registered system structure.
It realizes \ref{req:SR-10-02} and \ref{req:SR-10-03} for execution ordering under \ref{req:UR-10}.
It also realizes \ref{req:SR-11-02} for algebraic-loop detection under \ref{req:UR-11}.
The analysis uses the registered components, signal connections, and direct-feedthrough information.
Coupled initialization and the master algorithms consume the resulting metadata during simulation.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{Inputs, Outputs, and Stored Metadata}
\label{sec:impl_structural_inputs}

Structural analysis uses the registered components, the signal connections, and the per-component direct-feedthrough metadata stored on the \texttt{System}.
It also derives the active outputs from the connection list.
Active outputs are output ports referenced by at least one outgoing signal connection.

The derived metadata is stored on the \texttt{System} instance.
Initialization and the master algorithms can therefore reuse it without recomputing the graphs.
Table~\ref{tab:structural_metadata} lists the stored fields, their producer routine, and their purpose.

\subsection{Graph Construction and Loop Detection}
\label{sec:impl_structural_graph}

The \texttt{build\_graphs()} method performs graph construction.
It clears previously cached structural metadata and adds every registered component as a node of both \texttt{graph} and \texttt{\_dag}.
This keeps isolated components visible even when they have no signal connections.
The method then derives the set of active outputs from the connection list.
A final pass over the registered connections builds the full connection graph, the zero-delay graph, and the input lookup maps.

\paragraph{Full Connection Graph.}
During the connection pass, every signal connection is added to \texttt{graph} as an annotated multi-edge.
Figure~\ref{fig:struct_worked_a} shows the registered input data.
Figure~\ref{fig:struct_worked_b1} shows the resulting full connection graph.
The \texttt{src\_port} and \texttt{dst\_port} attributes identify the connected ports.
The same pass fills the input lookup maps listed in Table~\ref{tab:structural_metadata}.
Downstream routines can therefore resolve the driver of an input port without traversing the graph.

\paragraph{Zero-Delay Graph and Active-Output Filter.}
Execution ordering uses only instantaneous dependencies.
The \texttt{\_dag} graph therefore contains only connections that contribute to direct feedthrough.
A connection into a component is inserted when the destination input influences at least one active output of that component.
Figure~\ref{fig:struct_worked_b2} shows the resulting zero-delay graph for the worked example.
The active-output filter removes dependencies that cannot affect another component during the same communication point.
This is a \syssimx{} implementation detail beyond the conceptual graph of Section~\ref{sec:233_cosim_structural_analysis}.

\paragraph{Algebraic Loop Detection.}
After assembling the zero-delay graph, the graph builder detects instantaneous cyclic dependencies.
It computes the strongly connected components of \texttt{\_dag} with NetworkX.
Each component set with more than one node is stored as one loop block in \texttt{algebraic\_loops}.
In Figure~\ref{fig:struct_worked_b2}, the dashed red boundary marks the detected loop block formed by components~B and~C.
The IJCSA solver of Section~\ref{sec:impl_algebraic_loops} treats this block as an unordered set of interface unknowns and equations.

\paragraph{Self-Loops.}
A one-component algebraic loop arises when an outer connection feeds an active output of a component back into one of its own direct-feedthrough inputs.
Such a configuration produces a self-loop in \texttt{\_dag}.
Singleton SCCs are not sufficient to identify this case because isolated components are also returned as singleton sets.
A second pass therefore appends every node with a self-loop edge as a singleton entry of \texttt{algebraic\_loops}.
This unified representation lets the IJCSA solver apply the same iteration scheme to multi-component and one-component loops.

\subsection{Execution Order}
\label{sec:impl_structural_condensation}

The \texttt{compute\_execution\_order()} method condenses the zero-delay graph and derives the generation-based schedule.
The condensation follows the structural-analysis principle introduced in Section~\ref{sec:233_cosim_structural_analysis}.
The resulting schedule is stored in \texttt{execution\_order} and consumed by initialization and the master algorithms.

\paragraph{Condensation.}
The condensation is obtained through \texttt{networkx.condensation()}.
The result is a directed acyclic graph whose nodes are identifiers of the strongly connected components of \texttt{\_dag} and whose edges reflect the inter-component dependencies that survive the collapse.
Figure~\ref{fig:struct_worked_d} shows the resulting condensed graph and the corresponding \texttt{execution\_order} before delayed-producer post-processing.
The mapping from component names to condensation identifiers is stored in \texttt{\_scc\_index} so that the initialization loop and the IJCSA solver can locate the loop block of any component in constant time.

\paragraph{Topological Generations.}
The condensed graph is acyclic and can therefore be ordered generation by generation.
The implementation computes these generations with NetworkX.
Each generation is a set of condensation nodes in the sense of Section~\ref{sec:233_cosim_structural_analysis}.
\syssimx{} expands each condensation node to its component names.
It sorts the component names alphabetically and stores the resulting list of lists in \texttt{execution\_order}.
A generation therefore contains either mutually independent components or the members of one algebraic loop.
The same pass builds \texttt{execution\_idx}, which maps each component name to its generation index.

\paragraph{Delayed Producer Post-Processing.}
The condensed schedule captures all instantaneous ordering constraints.
Components that are isolated in \texttt{\_dag} may still influence the coupled part of the system through delayed paths in \texttt{graph}.
\syssimx{} classifies such components as delayed producers and moves them to a final generation.
Figure~\ref{fig:struct_worked_d} shows this relocation for component~D.
The \texttt{is\_delayed\_producer()} predicate checks for components without incident zero-delay edges.
It then tests whether such a component can still reach a component with zero-delay structure through the full graph.
After relocation, \texttt{execution\_idx} is rebuilt so that the lookup remains consistent with \texttt{execution\_order}.
This relocation is a \syssimx{} scheduling choice.

\paragraph{Consumers of Structural Metadata.}
Structural metadata is computed once during \texttt{initialize(t0)}.
Initialization and the master algorithms consume it read-only.
They traverse the stored execution order, propagate inputs through the input-source map, and identify loop blocks through \texttt{algebraic\_loops}.
Section~\ref{sec:impl_algebraic_loops} describes how these loop blocks are solved.

The system graph visualizer consumes the same metadata.
It renders component groups, port labels, signal and event connections, execution-order indices, and algebraic-loop edges.
The visualizer supports \ref{req:UR-12} as an inspection helper.
It is not part of the simulation semantics.

\subsection{Verification}
\label{sec:impl_structural_verification}

The structural-analysis verification uses the four-component scenario of Figure~\ref{fig:struct_worked}.
The scenario is small enough to inspect manually, but it exercises the complete metadata path from registered connections to the final execution order.
The expected full connection graph contains all registered signal connections.
The expected zero-delay graph contains only the instantaneous dependencies induced by the direct-feedthrough maps of components~B and~C.
Components~A and~D expose no direct feedthrough and therefore do not contribute zero-delay edges.

Table~\ref{tab:structural_verification} summarizes the expected and observed metadata.
The result confirms that the implementation preserves the full connection structure in \texttt{graph} and filters the instantaneous structure into \texttt{\_dag}.
It also detects the loop block formed by components~B and~C.
The execution-order computation condenses this loop block into one generation and moves component~D to the final generation as a delayed producer.
