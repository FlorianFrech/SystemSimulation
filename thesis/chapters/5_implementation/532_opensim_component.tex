\subsection{Musculoskeletal Model Wrapper}
\label{sec:impl_opensim}

The \texttt{OpenSimComponent} class adapts OpenSim models to the \texttt{CoSimComponent} interface of Section~\ref{sec:impl_component_interface}.
It realizes \ref{req:SR-06-01} under \ref{req:UR-06}.
The wrapper delegates multibody and muscle dynamics to OpenSim and Simbody.
It exposes the OpenSim realize--integrate cycle through the primitive operations of the component contract.

As described in Section~\ref{sec:242_modeling_musculoskeletal}, an OpenSim model advances a \texttt{State} through a \texttt{Manager}.
Derived quantities are obtained by staged realization of that state.
Concrete OpenSim-based components define their own ports, parameters, model assembly, and transferable state.

\subsubsection{Architecture and Interface Mapping}

Figure~\ref{fig:impl_opensim_class} shows how the OpenSim wrapper connects the framework contract to the OpenSim runtime objects.
The \texttt{OpenSimComponent} class is an abstract base class.
OpenSim does not provide a standardized co-simulation descriptor comparable to \texttt{modelDescription.xml}.
Each concrete subclass therefore defines the ports, parameters, model assembly, stepping logic, and state-transfer methods.
The base class provides only the OpenSim infrastructure shared by these subclasses.

\subsubsection{Lifecycle Realization}

The base class provides shared support for the OpenSim lifecycle.
A concrete subclass builds or loads the \texttt{Model}, declares the component ports, applies model-specific parameters, and calls \texttt{initSystem()}.
This produces the initial \texttt{State}.

The helper \pyfn{\_finalize\_model(t0)} completes the common part of initialization.
It realizes the state to the \textit{Acceleration} stage and creates a \texttt{Manager}.
It then configures the integrator, initializes the manager, and sets the simulation time to $t_0$.
After the inherited template method returns, the initial outputs are stored in the port states and recorded in the component history.

Time stepping remains a responsibility of the concrete subclass.
The subclass writes current input values into the OpenSim state and advances the model through the OpenSim \texttt{Manager}.
The communication step $\Delta t$ defines the synchronization boundary of the coupled simulation.
OpenSim and Simbody handle the internal step-size selection through the configured integrator.

Output refresh is also model-specific.
A concrete subclass realizes the state to the required OpenSim stage and reads the quantities that correspond to its declared output ports.
The results are written back into the \texttt{PortState} objects with their declared units.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsubsection{State Access and Rollback Boundary}

State access remains part of the concrete subclass contract.
The transferable state depends on the selected coordinates, actuator states, muscle states, and model-specific assumptions.
The \texttt{OpenSimComponent} class provides helper methods for reading and writing generalized positions, speeds, and accelerations by coordinate name.
Concrete subclasses can use these helpers to implement state transfer for multi-model switching.

Rollback for hybrid co-simulation also remains subclass-specific.
A rollback-capable OpenSim component must restore both the model state and the integrator state consistently.
The generic base class therefore leaves \texttt{snapshot\_state()} and \texttt{restore\_state()} to specialized subclasses.
