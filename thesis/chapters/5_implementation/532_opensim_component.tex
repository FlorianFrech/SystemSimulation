\subsection{Musculoskeletal Model Wrapper}
\label{sec:impl_opensim}

This subsection describes the \texttt{OpenSimComponent} wrapper.
It realizes SR-03-02 by adapting OpenSim models to the \texttt{CoSimComponent} interface of Section~\ref{sec:impl_component_interface}.
The wrapper delegates multibody and muscle dynamics to OpenSim and Simbody.
It encapsulates the realize--integrate cycle behind the primitive operations of the component contract.

As described in Section~\ref{sec:242_modeling_musculoskeletal}, an OpenSim model advances an \texttt{osim.State} through a \texttt{Manager}.
Derived quantities are obtained by staged realization of that state.
The wrapper does not replace this machinery.
It provides a reusable base for concrete musculoskeletal components whose ports and model assembly remain model-specific.

\subsubsection{Architecture and Interface Mapping}

Figure~\ref{fig:impl_opensim_class} shows the class-level relationship between \texttt{OpenSimComponent}, \texttt{CoSimComponent}, and the external OpenSim objects.
Unlike \texttt{FMUComponent} (Section~\ref{sec:impl_fmu}), \texttt{OpenSimComponent} is an abstract base class.
OpenSim models do not provide a standardized co-simulation descriptor comparable to \texttt{modelDescription.xml}.
A concrete subclass therefore defines the ports, parameters, model assembly, stepping logic, and state-transfer methods.
The base class provides only the OpenSim infrastructure shared by these subclasses.

\paragraph{Direct-Feedthrough Detection.}
OpenSim does not declare input--output dependencies in a standardized descriptor.
The wrapper therefore relies on the perturbation-based detector inherited from \texttt{CoSimComponent} (Section~\ref{sec:impl_component_interface}).
For the musculoskeletal components used in this thesis, actuator inputs affect outputs through the OpenSim state dynamics.
They therefore do not introduce port-level direct feedthrough in the implemented scenarios.

\subsubsection{Lifecycle Realization}

The base class provides shared support for the OpenSim lifecycle.
A concrete subclass builds or loads the \texttt{osim.Model}, declares the component ports, applies model-specific parameters, and calls \texttt{initSystem()} to obtain the initial \texttt{osim.State}.

The helper \texttt{\_finalize\_model(t0)} completes the common part of initialization.
It realizes the state to the \textit{Acceleration} stage, creates an \texttt{osim.Manager}, configures the integrator method and accuracy, initializes the manager, and sets the simulation time to $t_0$.
After the inherited template method \texttt{initialize()} returns, the initial outputs are stored in the port states and recorded in the component history.

Time stepping remains a responsibility of the concrete subclass.
The subclass writes current input values into the OpenSim state and advances the model through the OpenSim \texttt{Manager}.
The communication step $\Delta t$ defines the synchronization boundary of the coupled simulation.
The internal step-size selection is handled by the OpenSim and Simbody integrator configuration.

Output refresh is also model-specific.
A concrete subclass realizes the state to the required OpenSim stage and reads the quantities that correspond to its declared output ports.
The results are written back into the \texttt{PortState} objects with their declared units.

\subsubsection{State Access and Rollback Boundary}

The generic \texttt{OpenSimComponent} does not implement \texttt{get\_state()} or \texttt{set\_state()}.
These methods remain part of the concrete subclass contract.
This is necessary because the transferable state depends on the selected coordinates, actuator states, muscle states, and model-specific assumptions.

The base class provides coordinate helper methods for reading and writing generalized positions, speeds, and accelerations by coordinate name.
Concrete subclasses can use these helpers to implement state transfer for multi-model switching.
This keeps the generic wrapper independent of a particular musculoskeletal model.

The generic base class also does not implement \texttt{snapshot\_state()} or \texttt{restore\_state()}.
Rollback for hybrid co-simulation must be implemented by specialized subclasses whose model state and integrator state can be restored consistently.
