\section{Master Algorithms}
\label{sec:impl_algorithms}

The master-algorithm implementation realizes \ref{req:SR-10-01}, \ref{req:SR-11-01}, and \ref{req:SR-11-03}.
It implements the execution strategies introduced in Section~\ref{sec:234_cosim_execution_strategies}.
The structural analysis of Section~\ref{sec:impl_structural} provides the execution generations and the detected algebraic loops.
The \ac{SCC}-local loop solver is described in Section~\ref{sec:impl_algebraic_loops}.
This section focuses on one macro step in \texttt{JacobiAlgorithm}, \texttt{GaussSeidelAlgorithm}, and \texttt{IJCSAAlgorithm}.
Hybrid event handling is covered separately in Section~\ref{sec:impl_hybrid}.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{Scope and Shared Metadata}
\label{sec:impl_algorithms_scope}

All master algorithms use the structural metadata computed during system initialization.
The execution order defines the generation order, and the algebraic-loop metadata identifies loop blocks.
Input propagation is performed generation by generation.
Jacobi and Gauss--Seidel reuse the \ac{SCC}-local solver of Section~\ref{sec:impl_algebraic_loops}.
The global \ac{IJCSA} algorithm solves one coupled interface problem before component stepping.

One macro step first prepares interface values and then advances the components from $t$ to $t+\Delta t$.
The algorithms differ in the ordering of preparation, correction, and stepping.

\subsection{Jacobi Algorithm}
\label{sec:impl_algorithms_jacobi}

The \texttt{JacobiAlgorithm} class realizes the explicit non-iterative scheme of Section~\ref{sec:234_cosim_execution_strategies}.
It structures one macro step in two phases.
The first phase follows the stored execution order and stages the interface values at the current communication point.
Local loop blocks are solved during this preparation step when needed.
The second phase advances every component with the staged interface values.

All components therefore use the same communication-point snapshot.
Components in later generations still read output values from the previous communication point.
The current implementation preserves this semantics through a serial loop.
The component steps of the second phase could be parallelized in principle, but this is not implemented.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

\subsection{Gauss--Seidel Algorithm}
\label{sec:impl_algorithms_gs}

The \texttt{GaussSeidelAlgorithm} class combines preparation and stepping in one pass over \texttt{execution\_order}.
For each generation, it stages the interface values, solves local loop blocks, and advances the contained components.
Outputs from earlier generations are therefore already updated when later generations receive their inputs.
This within-step visibility distinguishes the implementation from the Jacobi algorithm.

The local \ac{SCC} solver, the input-staging routine, and the structural metadata are reused unchanged.
Because generations are advanced sequentially, this implementation does not exploit parallelism.

\subsection{Global IJCSA Algorithm}
\label{sec:impl_algorithms_ijcsa}

The \texttt{IJCSAAlgorithm} class provides a global variant of the interface Newton solve.
It follows the interface-Jacobian idea of Sicklinger et al.~\cite{sicklinger_interface_2014}.
The implementation restricts this idea to the signal-assignment form used by \syssimx{}.
It collects all zero-delay interface inputs and solves one coupled residual problem.
This differs from the \ac{SCC}-local solver, which treats each loop block separately.

The \texttt{step()} method runs in two phases.
The first phase solves the global zero-delay interface.
It builds the global unknown vector, evaluates the residual with frozen component states, and applies a Newton iteration.
A damped-gradient fallback stabilizes the update when the Jacobian is singular.
After convergence, the solved interface values are written to the destination input ports.
The second phase traverses the stored execution order and advances every component.

The implementation is restricted to the signal-assignment residual $U=\widehat{U}(U)$.
It does not support general nonlinear interface constraints.
Residual evaluation uses component output evaluation without advancing accepted component time.
The interface Jacobian is assembled by finite differences.
Input extrapolation and explicit relaxation factors are not implemented.

The global solve can be more expensive than the local \ac{SCC} strategy because it assembles one interface system for all zero-delay inputs.
For scenarios with small or acyclic zero-delay structures, this provides little benefit over generation-based propagation and local loop solving.
\texttt{IJCSAAlgorithm} is therefore included mainly as a reference implementation of a global interface solve.
The default continuous path remains \texttt{GaussSeidelAlgorithm}, while \texttt{JacobiAlgorithm} is available for comparison.

\subsection{Verification}
\label{sec:impl_algorithms_verification}

The verification uses a small feedback scenario with a constant source, a gain block, a subtractor, and an integrator.
The integrator has no direct feedthrough.
The zero-delay graph is therefore acyclic and the structural analysis produces three generations without \acp{SCC}.
Figure~\ref{fig:impl_algorithms_verification_system} shows the topology.

\begin{figure}[!htbp]
    \centering
    \includegraphics[width=0.85\linewidth]{figures/5_implementation/master_algorithms/master_algorithm_verification.pdf}
    \caption[Feedback scenario for comparing the continuous master algorithms]{Feedback scenario for comparing the continuous master algorithms.
    The integrator has no direct feedthrough, so the zero-delay graph is acyclic.}
    \label{fig:impl_algorithms_verification_system}
\end{figure}

The continuous dynamics reduce to the scalar \ac{ODE} $\dot{y}=K\,r-y$ with $y(0)=0$.
Its analytical solution
\begin{equation}
    y(t) = K\,r\,\bigl(1-e^{-t}\bigr)
\end{equation}
serves as the reference.

Figure~\ref{fig:impl_algorithms_verification} compares all three algorithms against this reference for four macro step sizes with $K=2$ and $r=1$.

\begin{figure}[t]
    \vspace{-1ex}
    \centering
    \includegraphics[width=0.9\linewidth]{figures/5_implementation/master_algorithms/algorithm_comparison.pdf}
    \caption[Step-size comparison of the continuous master algorithms]{Step-size comparison of the continuous master algorithms.
    The traces are compared against the analytical reference for decreasing macro step sizes.}
    \label{fig:impl_algorithms_verification}
\end{figure}

At $\Delta t = 0.5\,\mathrm{s}$, the Jacobi trace overshoots the analytical solution.
This is the largest coarse-step error in the comparison.
It is caused by the two-phase structure of the Jacobi algorithm.
Later generations read outputs from the previous communication point, so the feedback through the integrator reaches the subtractor with one macro-step delay.

The Gauss--Seidel trace stays closer to the analytical solution at the same step size.
Its generation-wise pass propagates the updated subtractor output within the same macro step and therefore tracks the reference more closely.

The \texttt{IJCSAAlgorithm} trace overlaps the Gauss--Seidel trace in this scenario because the zero-delay graph is acyclic.
The global solve handles the zero-delay interface inputs of the Gain and Subtractor components but does not resolve an algebraic loop.
After this consistency step, the algorithm advances the generations sequentially, which matches the Gauss--Seidel traversal for this example.

The scenario verifies the expected orchestration behavior of the three master algorithms.
It does not exercise algebraic-loop resolution because the zero-delay graph is acyclic.
The \ac{SCC}-local Newton solve is verified separately in Section~\ref{sec:impl_algebraic_loops}.
