\section{Component Interface}
\label{sec:impl_component_interface}

The \texttt{CoSimComponent} base class implements the component contract introduced in Section~\ref{sec:architecture_cosimcomponent}.
The port system from Section~\ref{sec:impl_port_system} provides the interface representation.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{Design}

\texttt{CoSimComponent} is implemented as an abstract base class following the template method pattern~\cite{gamma_design_1995}.

The base class defines three categories of methods, summarized in Table~\ref{tab:component_methods}.

%
\begin{table}[!htbp]
  \centering
  \small
  \caption{Role-based classification of \texttt{CoSimComponent} methods.
  Template methods define the public lifecycle interface and fix the invariant execution skeleton.
  Primitive operations are declared abstract and must be implemented by every subclass.
  Hook operations are optional override points, some provide a default no-op implementation, while others raise \texttt{NotImplementedError} until a subclass opts in.}
  \label{tab:component_methods}
  \begin{tabular}{llp{5.8cm}}
    \toprule
    \textbf{Method} & \textbf{Contract} & \textbf{Purpose} \\
    \midrule
    \texttt{initialize(t0)}                              & Template  & Component lifecycle startup \\
    \texttt{do\_step(t, dt)}                             & Template  & Macro time step \\
    \texttt{handle\_event(event\_names, t)}              & Template  & Event handling and output refresh \\
    \midrule
    \texttt{\_initialize\_component(t0)}                 & Primitive & Component-specific initialization \\
    \texttt{\_do\_step\_internal(t, dt)}                 & Primitive & Time step computation \\
    \texttt{\_update\_output\_states(t)}                 & Primitive & Write internal state to output ports \\
    \midrule
    \texttt{get\_state() / set\_state()}                 & Hook      & Physical state transfer \\
    \texttt{snapshot\_state() / restore\_state()}        & Hook      & Opaque state rollback \\
    \texttt{evaluate\_outputs(inputs, t)}                & Hook      & Zero-step output evaluation \\
    \texttt{\_handle\_events\_internal(event\_names, t)} & Hook      & Event-driven state update \\
    \texttt{reset()}                                     & Hook      & Clear state \\
    \bottomrule
  \end{tabular}
\end{table}

The three-tier method organization produces an inverted control flow.
The co-simulation algorithm calls \texttt{do\_step()} on the base class, and the base class in turn calls into the subclass, not the other way around.
Generic framework concerns such as port-state management, time bookkeeping, history recording, and capability detection are therefore implemented once in the base class and apply uniformly to all components, regardless of the underlying simulation backend.

\subsection{Runtime State}

\paragraph{Identity and Organization.}
Each component is assigned a unique \texttt{name} at construction, which serves as its primary identifier within the \texttt{System}.
The name is used for connection definitions, dependency graph construction, error reporting, and history labeling.
An optional \texttt{group} string allows components to be categorized for system graph visualization.

\paragraph{Interface Representation.}
The port interface is represented at two levels
Immutable \emph{port specifications} (\texttt{input\_specs}, \texttt{output\_specs}) are declared by the subclass at construction, and mutable \emph{port states} (\texttt{inputs}, \texttt{outputs}) are instantiated from the specifications during initialization and updated on every simulation step (Section~\ref{sec:impl_port_system}).

\paragraph{Execution and History State.}
The current simulation time \texttt{t} is updated by the \texttt{do\_step()} after each successful step.
The boolean flag \texttt{\_is\_initialized} prevents double initialization.
The \texttt{history} attribute is a \texttt{ComponentHistory} instance that records time-stamped output port values after every step, enabling result retrieval after the simulation loop.

\paragraph{Structural and Hybrid Metadata.}
The \texttt{direct\_feedthrough} attribute maps each output port to the set of input ports it depends on algebraically.
It is populated automatically by \texttt{\_detect\_direct\_feedthrough()} during initialization and consumed by the \texttt{System} to identify algebraic loops and determine execution order (Section~\ref{sec:impl_system}).
Components that participate in hybrid simulation register zero-crossing functions in \texttt{event\_indicators} and external event subscriptions in \texttt{event\_subscriptions}.
Additional metadata for event ordering and micro-step timing hints supports the hybrid algorithm and is described in Section~\ref{sec:impl_hybrid}.

\subsection{Lifecycle Semantics}

\paragraph{Construction.}
Figure~\ref{fig:impl_comp_construction} shows the construction sequence.
The subclass constructor calls the base class constructor via \texttt{super().\_\_init\_\_()}, which allocates the internal containers for port specifications, parameters, and history recording.
The subclass then populates \texttt{input\_specs} and \texttt{output\_specs} with \texttt{PortSpec} objects that declare the component interface.

\begin{figure}[!htbp]
  \centering
  \includegraphics[width=0.8\linewidth]{diagrams/out/pdf/execution/CoSimComponent_Construction.pdf}
  \caption{Delegation during component construction. The subclass calls the base class constructor to allocate internal containers, then defines the port specifications that describe the component interface.}
  \label{fig:impl_comp_construction}
\end{figure}

\paragraph{Configuration.}
A component is configured via \texttt{set\_parameters()} befor initialization.
The method validates and stores keyword arguments into the \texttt{parameters} dictionary.
Keys and value types are defined by each subclass which declare the available parameters, their defaults parameters, and apply them inside \texttt{\_initialize\_component()}.

\paragraph{Initialization.}
The initialization sequence is shown in Figure~\ref{fig:impl_comp_initialization}.
The template method \texttt{initialize(t0)} is idempotent.
If the component has already been initialized, the method returns immediately and leaves the existing runtime state unchanged.
Otherwise, the base class first stores the initial simulation time~\texttt{t0}.
It then creates \texttt{PortState} objects from the declared input and output \texttt{PortSpec} objects.
After the regular ports have been instantiated, the base class creates event output ports for all event indicators that were registered before initialization.

The template method then delegates to the primitive operation \texttt{\_initialize\_component(t0)}, which performs all component-specific setup required before the simulation can start.
After this model-specific initialization has completed, the base class detects direct feedthrough dependencies in the component's input-output structure.
It then calls \texttt{\_update\_output\_states(t0)} to publish the initial outputs, records these values in the component history via \texttt{\_record\_outputs(t0)}, and finally marks the component as initialized.


\begin{figure}[!htbp]
  \centering
  \includegraphics[width=0.8\linewidth]{diagrams/out/pdf/execution/CoSimComponent_Initialization.pdf}
  \caption{Delegation during component initialization. The template method
    \texttt{initialize()} performs the idempotency check, creates regular
    and event ports, delegates model-specific setup to
    \texttt{\_initialize\_component()}, detects direct feedthrough, publishes
    initial outputs through \texttt{\_update\_output\_states()}, and records
    the initial output values.}
\end{figure}

\paragraph{Simulation Step.}
Figure~\ref{fig:impl_comp_stepping} shows the delegation during a single macro time step.
The co-simulation algorithm calls the template method \texttt{do\_step(t,\,dt)}, which delegates the numerical computation to the primitive operation \texttt{\_do\_step\_internal()}.
This method advances the internal model state from~$t$ to~$t + dt$.
After \texttt{\_do\_step\_internal()} returns, the template method updates the component time and calls \texttt{\_update\_output\_states()} to refresh the output ports with the new state, then records the updated values in the component history.

\begin{figure}[!htbp]
  \centering
  \includegraphics[width=0.8\linewidth]{diagrams/out/pdf/execution/CoSimComponent_Stepping.pdf}
  \caption{Delegation during a simulation step. The template method
    \texttt{do\_step()} delegates the computation to the primitive operation
    \texttt{\_do\_step\_internal()} and the output update to
    \texttt{\_update\_output\_states()}.}
  \label{fig:impl_comp_stepping}
\end{figure}

\paragraph{Event Handling.}
The template method \texttt{handle\_event(event\_names,\,t)} is called by the hybrid algorithm at event times (Section~\ref{sec:impl_hybrid}).
It delegates the state update to the hook operation \texttt{\_handle\_events\_internal()}, then calls \texttt{\_update\_output\_states()} to refresh the output ports, and records the updated values in the component history.
Components that do not participate in hybrid simulation inherit an empty default for \texttt{\_handle\_events\_internal()}, so the call is a no-op.

\paragraph{Reset and Cleanup.}
After the simulation loop, the hook operation \texttt{reset()} supports component reuse.
It clears the simulation time, history buffer, and initialization flag, allowing the component to be re-initialized with \texttt{initialize()} for a new run.
Subclasses extend the default implementation via \texttt{super().reset()} to
additionally clear internal state.

\subsection{Verification}

The verification of \texttt{CoSimComponent} targets framework-level invariants that are independent of any backend.
Lightweight mock subclasses, such as a pure-gain feedthrough component, a simple integrator, and minimal hybrid components, implement only the three primitive operations, keeping the tests focused on base-class behavior.

Table~\ref{tab:cosimcomp_verification} summarizes the verified properties.

  \centering
  \small
  \caption{Verified properties of \texttt{CoSimComponent}.
    All tests use lightweight mock subclasses and target base-class

      & Primitive operations called in sequence; initial outputs recorded in history \\
    \addlinespace

      & Time updated after step; output ports refreshed and values recorded \\
    \addlinespace

      & Compatible values accepted; wrong type and unknown name raise an exception \\

The tests confirm that \texttt{CoSimComponent} reliably enforces the component contract for any subclass.
Port states are instantiated from specifications during initialization, the template methods maintain the correct delegation order, parameters are validated before use, and direct feedthrough metadata is gathered automatically.
Hook operations, such as state transfer, rollback, and event handling, are intentionally excluded from this verification scope, as their correctness depends on the concrete model semantics provided by each backend wrapper.
