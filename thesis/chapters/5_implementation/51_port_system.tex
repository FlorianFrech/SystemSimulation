\section{Port System}
\label{sec:impl_port_system}

This section describes the implementation of the port system, which realizes the typed port interface of the \texttt{CoSimComponent} contract introduced in Section~\ref{sec:architecture_cosimcomponent}.
It addresses the requirements SR-01-01 and SR-02-01 to SR-02-03.
The port system is used throughout the framework for connection validation, unit-aware value propagation, and event-port creation.

\paragraph{\texttt{PortSpec}.}
A \texttt{PortSpec} is implemented as a frozen dataclass and describes one port through its name, direction (\texttt{"in"} or \texttt{"out"}), data type, optional physical unit, and an optional human-readable description.
Unit strings are validated against the shared Pint registry at construction so that malformed specifications are rejected before a component is instantiated.
A static method \texttt{PortSpec.compatible()} defines the connection rule used by the \texttt{System} class.
Two specifications are compatible when their data types match exactly and, for \texttt{REAL} ports, either both units are \texttt{None} or both are present and dimensionally compatible.
This rule is consumed during connection registration in \texttt{System.\_validate\_connection} (Section~\ref{sec:impl_system}).

\paragraph{\texttt{PortState}.}
A \texttt{PortState} holds the mutable runtime value of a port during simulation and references the corresponding \texttt{PortSpec}.
Each state stores the current value and the timestamp of the last update.
On \texttt{set()}, the value is validated against the specification, and \texttt{REAL} values are converted to the port's declared unit.
On \texttt{get()}, the caller may request a target unit for conversion, which allows downstream code to read values in whichever unit is convenient without losing dimensional information.
Port states are instantiated from the registered specifications during component Initialization.

\subsection{Physical Unit Handling}
\label{par:impl_units}

Physical units are managed through the Pint library~\cite{grecco_pint_nodate}, which provides a unit registry, dimensional analysis, and automatic conversion between compatible units.
The framework initializes a single shared registry that is used by all ports and components.
Unit enforcement happens at three points in the workflow.
At port construction, the declared unit string is validated against the registry and unrecognized strings are rejected.
At connection time, the \texttt{System} checks dimensional compatibility between source and destination ports via \texttt{PortSpec.compatible()}.
At runtime, every call to \texttt{PortState.set()} converts the incoming value to the port's declared unit, and incompatible dimensions raise an error.

To support FMI~2.0 Co-Simulation FMUs exported from OpenModelica, the registry is preceded by a pre-processing step that normalizes FMI-style unit strings.
OpenModelica uses a compact exponent notation such as \texttt{"m.s-2"} for $\text{m}\,\text{s}^{-2}$, which is not directly recognized by Pint.
The framework translates such strings to the standard form before passing them to the registry.
