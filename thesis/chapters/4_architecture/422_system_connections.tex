\subsection{System and Connections}
\label{sec:architecture_system_connections}

The \texttt{System} class represents the assembled co-simulation model.
It collects components, signal connections, event connections, and direct-feedthrough declarations.
It also provides the structural context used by initialization and execution.
This separates the definition of individual components from the definition of the coupled system.

Figure~\ref{fig:system_architecture} illustrates a user-defined system in \syssimx{}.
It shows four components with typed input and output ports, signal connections, one event connection, and per-component direct-feedthrough paths.
The implementation-level structural metadata derived from this definition is discussed later in Section~\ref{sec:impl_structural}.

The \texttt{System} supports signal connections and event connections.
A signal connection defines directed data flow from an output port of one component to an input port of another component.
An event connection routes a named event from an event source to an event listener.
This supports discrete interactions between components, such as mode changes or contact-triggered resets.

The \texttt{System} validates connections when they are added.
For signal connections, it checks that the referenced ports exist and that their declared types and units are compatible.
This makes coupling assumptions explicit at the system boundary.

The registered components and connections define the structural context for orchestration.
Together with the direct-feedthrough declarations of the components, this context determines which components can be evaluated independently and which components require coupled treatment.

The \texttt{System} does not own the numerical stepping scheme.
It holds the assembled model structure and delegates time advancement to an algorithm object.
This keeps model assembly separate from execution strategy.
