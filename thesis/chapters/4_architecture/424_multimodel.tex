\subsection{Multi-Model Component}
\label{sec:multi_model_component}

The class \texttt{MultiComponent} extends the \texttt{CoSimComponent} abstraction to the case where several interchangeable \emph{models} represent the same physical subsystem at different levels of fidelity or with different modeling approaches.
It provides a single external component interface while managing multiple internal model realizations.
Each model is itself a \texttt{CoSimComponent} instance, which allows the \texttt{MultiComponent} to delegate lifecycle and stepping calls to the currently active model through the same interface.
This abstraction is the basis for multi-fidelity simulation and runtime model switching in \syssimx{}.
Figure~\ref{fig:multi_component} illustrates the internal structure and the external view of the abstraction.

\begin{figure}[htbp]
  \centering
  \includegraphics[width=\textwidth]{figures/4_architecture/multi_component.pdf}
  \vspace{-1em}
  \caption{Architectural overview of the \texttt{MultiComponent} abstraction.
  The upper panel shows the internal structure: multiple interchangeable models are registered under a single component wrapper. The mode selector determines the active model based on the current state. On a mode switch, the state adapter transfers and adapts the physical state to the target model. The lower panel shows the external view: the surrounding system interacts only with the active model through unified input and output ports.}
  \vspace{-0.5em}  
  \label{fig:multi_component}
\end{figure}

At any point in time, exactly one internal model is active, as indicated by the highlighted element in Figure~\ref{fig:multi_component}.
This makes it possible to switch between models, for example between a computationally inexpensive rigid-body model and a high-fidelity finite element model, without altering the system structure.

A change of the active model requires state synchronization between the outgoing and the incoming model.
The \texttt{MultiComponent} uses physical state transfer for this purpose, because the transferred quantities must be interpretable by a model with a potentially different internal formulation.
If the state representations differ, a user-provided state adaptation function maps the exported state to the format expected by the target model.

To avoid rapid switching near decision boundaries, the abstraction supports hysteresis through a configurable minimum dwell time or switching margin.
This prevents chattering and reduces unnecessary switching overhead.
The detailed switching mechanism and its integration with the hybrid algorithm are discussed in Section~\ref{sec:impl_multi_model}.

With the architectural layers and their responsibilities established,  the following chapter describes the implementation, starting with the port system and proceeding through the component interface, the tool-specific wrappers, system orchestration, and the co-simulation algorithms.
